# РукаХод: структура проекта

Статус: проектное решение для следующего этапа. Текущий `ui/` — первый вариант экрана с настройкой адресов и клиентами старых WebSocket-протоколов; серверная часть в этот репозиторий пока не перенесена.

## Один репозиторий

```text
rukahod/
  ui/             единый браузерный пульт
  robot/          локальный сервер пульта и адаптеры к ROS 2
  description/    модель ровера и манипулятора, mesh и параметры суставов
  config/         камеры, адреса устройств, лимиты и режимы
  launch/         запуск всей системы
  scripts/        сборка и запуск одной командой
  docs/           контракт и инструкции
```

Папки добавляются по мере реализации. В Git всё живёт и версионируется вместе. Если ROS 2 потребует больше одного `package.xml` для разных типов сборки, эти пакеты останутся внутри этого репозитория.

## Запуск на машине ровера

Локальный HTTP-сервер отдаёт собранный `ui/`. Пульт держит два независимых WebSocket-соединения с компьютером ровера: для манипулятора и для ходовой части. На первом этапе сохраняем привычные порты `8765` (arm) и `8766` (rover), чтобы переиспользовать реализации из `silverhand_ws_gateway`. Оба сервера и их ROS-адаптеры живут в репозитории РукаХода; HTTP-сервер, arm и rover запускаются вместе, но отказ руки не останавливает ровер.

После переноса gateway аппаратные интерфейсы `ros2_control` отслеживают входящие Cyphal heartbeat физических узлов. CAN-транспорт работает и до готовности, чтобы принимать heartbeat; аппаратный компонент переходит в `ACTIVE` только при подтверждённой связи. При потере heartbeat компонент сообщает ошибку и использующий его контроллер останавливается. ROS-адаптер gateway проверяет состояние аппаратного компонента и контроллера через `controller_manager`: WS-порт домена открывается только при их готовности, а при потере готовности закрывает активные соединения и перестаёт принимать команды. Восстановление активации предусмотрено отдельно для руки и ровера, чтобы отсутствие питания руки не отключало WS ровера. Отдельный supervisor или Cyphal-приёмник в gateway не нужен. Пульт считает установленное WS-соединение признаком доступности домена; телеметрия и ошибки остаются для отображения состояния. Порядок реализации: [gateway-implementation-plan.md](gateway-implementation-plan.md).

В текущем прототипе серверная часть ещё не перенесена, поэтому UI пока дополнительно проверяет свежесть телеметрии. Эту временную проверку убираем после реализации описанного правила на серверах.

Для единственного оператора оба сервера должны согласованно признавать одну активную сессию; две независимые вкладки не должны делить управление рукой и ровером. Потеря rover-сессии или устаревшие команды движения останавливают ровер. Подтверждение аварийного останова приходит от робота, а не выводится из нажатия кнопки.

Два видеопотока: фронтальная камера и камера манипулятора. Их адреса задаются в конфигурации сервера; браузер получает конфигурацию вместе со страницей. Жёстко прописанные IP и старые третьи камеры в текущем прототипе подлежат удалению при подключении API.

## Границы первого этапа

Актуальная модель руки находится в сабмодуле `robot/RUKA2/ruka2_description`. Составная URDF для браузера, лимиты и цепочка FK/IK генерируются из неё перед запуском или сборкой UI; рука подключена к модели ровера без захвата. Сгенерированные файлы не коммитятся. В UI используется численный IK для предпросмотра; перед включением аппаратных декартовых команд нужно отдельно проверить допустимые траектории и поведение при недостижимой цели.

`ui/src/transport` и `ui/src/rover/transport` соединяются с `robot/rukahod_ws_gateway` на портах `8765` и `8766`. Mock-режимы и оба ROS-режима проверены на mock `ros2_control`; реальные Cyphal устройства ещё требуют проверки на железе.
