# План переноса gateway и ROS-адаптеров

Статус: `ruka2_control` и `ruka2_description` подключены через сабмодуль `robot/RUKA2`, ровер и `rukahod_ws_gateway` находятся в `robot/`. Входящие heartbeat проверяются аппаратными интерфейсами. Gateway перенесён; mock-протокол обоих доменов и ROS-режимы руки и ровера проверены на mock `ros2_control`. Для руки проверено выполнение траектории через WS, для ровера — закрытие и повторное открытие порта при остановке и возвращении controller manager. Запуск на реальном железе и сверка Cyphal node ID ровера остаются открытыми.

## 1. Уточнить аппаратный сигнал готовности

- Для руки и ровера сверить фактические Cyphal node ID физических устройств и частоту их входящих `uavcan.node.Heartbeat`. Не считать heartbeat, который отправляет компьютер, и не выводить node ID из `motor_id` без проверки.
- Задать список обязательных узлов каждого домена и таймаут относительно их реального периода. Определить, требуется ли готовность всех приводов или есть допустимые частичные конфигурации.
- Проверить, что при выключении питания и возврате питания входящий heartbeat соответственно пропадает и восстанавливается.

Актуальный `ruka2_control` уже отслеживает heartbeat и feedback узлов `21–26`. Ровер требует явный параметр `heartbeat_node_ids`; реальные ID ровера ещё нужно сверить с устройствами. Запуск CAN-транспорта (`is_up()`) сам по себе не подтверждает связь с физическими узлами.

## 2. Доработать существующие аппаратные интерфейсы `ros2_control`

- Использовать готовый `HeartbeatReader` из `ruka2_control` для руки; в роверном Cyphal runtime добавлена аналогичная подписка. В обработчиках учитываются `remote_node_id` и время последнего входящего heartbeat. Рука также читает `health` и `mode`.
- Держать CAN-транспорт включённым до активации, чтобы получать heartbeat. `on_activate` разрешает переход в `ACTIVE` лишь при готовности нужных узлов. Проверка не должна блокировать цикл управления на длительное время.
- Во время работы рука проверяет свежесть heartbeat и feedback на каждом сотом цикле `read()` при 100 Гц, ровер — heartbeat на каждом сотом цикле `write()` при 20 Гц. При потере обязательного узла аппаратный интерфейс возвращает ошибку, чтобы `controller_manager` остановил связанные контроллеры. Для ровера это около 5 секунд между проверками сверх заданного таймаута; до аппаратной эксплуатации нужно подтвердить допустимость этой задержки и независимый watchdog приводов.
- Обеспечить независимое состояние аппаратных компонентов руки и ровера. Настроить начальные lifecycle-состояния так, чтобы отсутствие одного компонента не прерывало запуск общего `controller_manager`.

## 3. Перенести старый `silverhand_ws_gateway`

- Перенести сервер, arm/rover ROS-адаптеры, протокол и mock-режимы в этот репозиторий, сохранив порты `8765` и `8766` и совместимость с текущим пультом.
- ROS-адаптер gateway получает через сервисы `controller_manager` состояния своего аппаратного компонента и контроллера. При готовности открывает WS-порт, при потере готовности закрывает порт и существующие соединения. Для этого потребуется небольшое изменение общего цикла сервера.
- Предусмотреть повторную попытку активации компонента и контроллера через lifecycle-сервисы после возвращения heartbeat. Запуск и восстановление руки не должны зависеть от ровера и наоборот.
- Mock-режимы открывают WS без аппаратной проверки и явно помечаются как mock.

## 4. Сохранить безопасное поведение команд

- Для ровера проверить сброс скорости при потере команд, WS-сессии или heartbeat; закрытие соединения не заменяет остановку на стороне управления.
- Для руки проверить отмену активного движения при пропаже аппаратной готовности.
- Ограничить управление одной операторской сессией для обоих доменов. Удалить протокол и обработчики захвата, которого в новой конфигурации нет.
- Сверить интерфейс gateway с актуальным `ruka2_control`: шесть суставов `joint_1`–`joint_6`, действие `/ruka_arm_controller/follow_joint_trajectory` и новая геометрия/лимиты URDF. Аппаратные команды включать после этой сверки.

## 5. Согласовать пульт и проверить сценарии

- Когда правило готовности на серверах проверено, убрать из UI временную проверку свежести `joint_state` и `rover_state` как условие доступности. WS-соединение станет признаком доступности; возраст телеметрии и ошибки останутся диагностикой.
- Проверить подключение и команды при двух включённых устройствах, при выключенной руке, при выключенном ровере, а также при пропадании и восстановлении heartbeat во время открытой операторской страницы.
- Критерий приёмки: WS каждого домена доступен только при активных аппаратном компоненте и контроллере; потеря heartbeat закрывает его соединения без влияния на другой домен; после восстановления пульт переподключается автоматически.
