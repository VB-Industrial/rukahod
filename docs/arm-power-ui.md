# Питание руки в UI

В настольной и мобильной панелях кнопки «Сложить / Разложить» находятся под
управлением движением. В самом низу — красная «Выкл» и зелёная «Вкл»,
заменяющие «Авария / Сброс Аварии». Поддерживаются RU/EN.

Управление идёт через WS ровера и доступно при отключённом WS руки:

- `set_arm_power`: `{command_id: string, enabled: boolean}`.
- `arm_power_result`: `{command_id, success, enabled, message}` — ответ на запрос.
- `arm_power_state`: `{available, commanded_enabled: boolean | null}` — состояние команды.

ROS-сервис `/power_board/set_arm_power` (`std_srvs/SetBool`) сохраняет канал
фар. Топик `/power_board/relay_commanded_state` (`std_msgs/Int8MultiArray`,
transient local, период 1 с) содержит `[реле руки, фары]`: 0 включает руку,
1 отключает. Для фар 1 включает, 0 отключает. При неизвестном состоянии
или отсутствии свежего сообщения в течение 3 с управление недоступно.

Релейный модуль не подтверждает фактическое положение контактов. Подпись
«Задано: Вкл/Выкл» показывает последнюю команду, а не наличие питания.
UI ждёт ответа backend, блокирует повторные запросы и показывает ошибки.
Перед отключением появляется подтверждение: приводы перестают удерживать руку.
Backend пытается отменить старую траекторию перед переключением питания;
включение отклоняется, если доступный action server не подтвердил отмену.

Загрузка страницы, потеря связи и реконнект не отправляют команды питания.
Проверка контракта без оборудования:

```sh
PYTHONPATH=robot/rukahod_ws_gateway python3 robot/rukahod_ws_gateway/scripts/arm_power_mock_test.py
```
